How Vanish works.

Vanish lets you send a password or private message as a link that stops working after it's read, or after a time limit, whichever comes first.

Your note is encrypted before it leaves your browser

When you press Create secret link, your browser generates a random 256-bit key and encrypts the note with AES-GCM. Only the encrypted bytes are sent to the server.

The key is placed after the # in the link. Browsers never send that part of a URL to any server, so the key stays between you and the person you share the link with.

Passphrases add a second lock

If you add a passphrase, the note is encrypted twice: first with a key derived from the passphrase, then with the link key. Someone who intercepts the link still can't read the note without the passphrase.

Notes destroy themselves

  • Each time the note is opened, the view count goes up in a single atomic database update. Two people can't both get the last view.
  • On the final view, the encrypted note is deleted immediately.
  • Unread notes are deleted automatically when their time runs out.
  • Link previews in chat apps can't use up a view, because opening a note needs a button press, not just a page load.

What the server can see

When a note was created, when it expires and how many views it allows. It can't see what the note says.

Built on Amazon EC2

Vanish runs as two Docker containers on one Amazon EC2 server: a small Python app that stores encrypted notes in SQLite, and Caddy, which serves it over HTTPS. Expired notes are deleted every minute.
